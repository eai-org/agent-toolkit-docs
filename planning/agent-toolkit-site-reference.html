The problem

Every project is a different world

  • Multiple projects different tech stacks, trackers, conventions
  • Teams differ in AI adoption fully agentic, chat only, and every hybrid in between
  • Project specific setups do not travel what works in one repo breaks in the next
  • I need workflows that work anywhere solo or in any team

"I needed a workflow that works just as well solo as it does with any team."

The answer

agent-toolkit

  • Generic skills and rules small, single purpose, composable
  • Project agnostic any codebase, any tracker
  • Agent agnostic Claude Code, OpenCode, Copilot, ...
  • Open source and evolving MIT, improved every day

Principles

Four ideas behind every skill

Keep the context lean
Stay in the Smart Zone. A full window makes a dumb agent.
Offload to files, pick up fresh
Write results to .md files. A clean session continues the work.
Human in the loop
Never guess, ask. The agent recommends, you decide.
Learn from mistakes
Every correction becomes a durable lesson in a skill or doc.

Context & memory hygiene

Know what auto loads /context-checkup

  • Audits everything that auto loads at startup CLAUDE.md chain, skill descriptions, MCP servers
  • Rough token cost per source measure, never guess
  • Lean, reversible trims, ranked by payoff nothing changes without your approval

"Your context is often cluttered before you even type."

Context & memory hygiene

Drain the agent memory /memory-doctor

  • Auto memory piles up unseen facts you never review, in every session context
  • Block by block: relocate, archive or keep you confirm every single action
  • Promote lessons to homes you control project docs, skills and rules, shared with the whole team

"Memory is an inbox, not a filing cabinet. Nothing should stay in it."

Task workflow

Refine, Plan, Act

TICKET.md → Refinethe WHATREQUIREMENTS.md → Planthe HOWPLAN.md → Actthe BUILDcode + checks
  • Each phase runs in a fresh session
  • Each phase produces a reviewable artifact
  • Mistakes get caught before any code is written

"The thinking is saved separately from the code."

Task workflow · step 0

Every task starts with a ticket /fetch-ticket

  • Any tracker Jira, GitHub, Azure DevOps, via the matching MCP
  • Grabs everything fields, comments, attachments, Figma design frames
  • Self contained TICKET.md saved in the planning directory, e.g. .agents/plans/1234-slug/
  • Fetch only no analysis, no planning, read only on the tracker
$ /fetch-ticket https://yourproject.atlassian.net/browse/XX-1234

Task workflow · refine

Define the WHAT /refine-ticket

  • Validates the ticket against the real codebase stale, ambiguous or contradicted requirements surface here
  • Grills you, one question at a time always with a recommended answer
  • Never guess, ask code answerable questions go to the code, the rest to you
  • Output: REQUIREMENTS.md self contained, ready for a fresh session

Talk to it like a colleague: steer, push back, brainstorm.

Task workflow · plan

Define the HOW /create-implementation-plan

  • Settles the technical decisions reuse vs build, which API, which tests, file structure
  • Docs outrank prior art existing code may predate the rule
  • Output: a self contained PLAN.md all the thinking, so the executor re derives nothing
  • A fresh session executes it then runs format, lint, test and build

Bad output is cheap to throw away when the thinking is preserved.

Task workflow

Why this works

  • Higher quality code especially as task complexity grows
  • Early review wrong assumptions die in REQUIREMENTS.md, not in the diff
  • Parallelism N refine and plan sessions at once, they only write .md files
  • Fits any team artifacts are plain markdown anyone can read, share or hand off
  • Fresh eyes verification another agent validates each artifact, no attachment to the output

/create-manual-test-instructions bonus: derive QA manual test steps from the same artifacts

Review assistants

Reviewing their code

  • review-ticket triage a ticket before anyone picks it up, only high value questions
  • review-code-assistant local review pass over a PR or branch, you decide what to post
  • fresh-eyes-review a fresh context catches what the authoring context reads past
  • check-ticket-implementation how much of a ticket is already done, requirement by requirement

The agent has the convention docs open and reads big files fast.

Review assistants

Handling reviews on your PRs

  • fetch-pr-review every reviewer comment into one self contained file
  • refine-pr-review triage together, comment by comment: address, partial or push back
  • Accepted changes become a REQUIREMENTS.md and flow straight back into the RPA pipeline
  • use-conversational-language replies sound like a colleague typed them, not an AI

"fixed", "good catch, thanks", "I would keep this as is because X, wdyt?"

Philosophy

agent-toolkit vs superpowers

superpowers

  • a whole methodology
  • skills auto activate before any task
  • the agent drives
  • pulls you in at its checkpoints
  • fuller context, less to remember

agent-toolkit

  • take the pieces you need
  • primarily user invoked
  • you drive, the agent assists
  • human in the loop by design
  • lean context, predictable behavior

The trade off: you always know what the agent loaded and why, but you must know your toolkit.
